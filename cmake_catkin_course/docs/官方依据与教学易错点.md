## 课程事实依据

### C++ 从单文件到多文件

GCC 将编译过程描述为预处理、编译、汇编和链接几个阶段。`-c` 会生成每个源文件对应的目标文件，并停止在链接之前。课堂可先执行 `g++ main.cpp -o wheelbot_demo`，随后拆分为多个 `.cpp`，分别编译成 `.o`，最后把对象文件一起交给 `g++` 链接。[GCC 编译阶段与 `-c`](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html)

头文件适合放供多个源文件共享的接口声明。`#include` 会把头文件内容纳入源文件预处理结果。普通函数的实现放在 `.cpp` 中；调用方的目标文件参与链接时，链接输入还需要包含提供该实现的对象文件。`g++` 会自动链接 C++ 标准库。[GCC 头文件说明](https://gcc.gnu.org/onlinedocs/cpp/Header-Files.html)，[GCC 的 g++ 说明](https://gcc.gnu.org/onlinedocs/gcc/Invoking-G_002b_002b.html)

贯穿案例约定为差速轮运动学，`v = r * (left + right) / 2`，`w = r * (right - left) / separation`。代码分为 `wheelbot_core` 计算库和 `wheelbot_ros` 节点包，ROS 层复用计算库。

### GNU Make 增量构建

Make 规则由目标、前置条件和 recipe 组成。目标文件不存在，或其时间戳早于任一普通前置条件时，Make 会执行 recipe。每条 recipe 默认以 TAB 开始。`$@` 指目标，`$<` 指首个前置条件，`$^` 指全部不重复的普通前置条件；自动变量在 recipe 中取值。[GNU Make 规则](https://www.gnu.org/software/make/manual/html_node/Rule-Syntax.html)，[自动变量](https://www.gnu.org/software/make/manual/html_node/Automatic-Variables.html)

手写规则阶段应将每个 `.o` 依赖的 `.cpp` 与相关头文件列为前置条件。后续扩展可用 GCC `-MMD -MP` 生成头文件依赖：`-MMD` 记录用户头文件，`-MP` 为依赖头文件生成空的伪目标，减少移除头文件后 Make 报缺失规则的情况。将生成的 `.d` 文件通过 `-include` 纳入 Makefile。[GNU Make 自动依赖建议](https://www.gnu.org/software/make/manual/html_node/Automatic-Prerequisites.html)，[GCC 依赖生成选项](https://gcc.gnu.org/onlinedocs/gcc/Preprocessor-Options.html)

### CMake 生成与构建

CMake 读取 `CMakeLists.txt`，配置项目并生成选定的构建系统。后续由对应的 Make、Ninja 等构建程序执行编译和链接命令。可使用 `cmake -S . -B build -G "Unix Makefiles"` 完成配置与生成，再用 `cmake --build build` 构建；也可选 `Ninja` 生成器。生成器由 CMake 选择或通过 `-G` 指定。[CMake 3.16.9 命令手册](https://cmake.org/cmake/help/v3.16/manual/cmake.1.html)，[Unix Makefiles 生成器](https://cmake.org/cmake/help/v3.16/generator/Unix%20Makefiles.html)，[Ninja 生成器](https://cmake.org/cmake/help/v3.16/generator/Ninja.html)

课程的普通 CMake 项目最低版本采用 3.16。`04_cmake` 中，`wheelbot_kinematics` 通过 `target_compile_features(wheelbot_kinematics PUBLIC cxx_std_11)` 和 `target_include_directories(wheelbot_kinematics PUBLIC ...)` 声明目标使用要求；同一构建图里的消费者 `wheelbot_demo` 链接该库后会接收这些 `PUBLIC` 要求。`PRIVATE` 项应用于当前目标。[CMake 3.16.9 `target_compile_features`](https://cmake.org/cmake/help/v3.16/command/target_compile_features.html)，[CMake 编译特性手册](https://cmake.org/cmake/help/v3.16/manual/cmake-compile-features.7.html)，[include 目录的可见范围](https://cmake.org/cmake/help/v3.16/command/target_include_directories.html)，[链接库的可见范围](https://cmake.org/cmake/help/v3.16/command/target_link_libraries.html)

`aux_source_directory()` 可收集目录中的源文件，但新增源文件时，生成系统无法仅凭此命令判断何时重新运行 CMake。主线显式列出目标源文件，新增文件时同时更新 `CMakeLists.txt`。[CMake 3.16.9 `aux_source_directory`](https://cmake.org/cmake/help/v3.16/command/aux_source_directory.html)

在源码根目录执行 `cmake .` 会把当前目录作为构建目录。CMake 支持这种同目录构建，并建议使用独立构建目录保持源码目录整洁。课堂统一用 `cmake -S . -B build`，让源码和构建产物分处两个目录。[CMake 3.16.9 源码树与构建树说明](https://cmake.org/cmake/help/v3.16/manual/cmake.1.html)

### catkin 包与工作空间

`catkin_make` 是 catkin 提供的命令，应从工作空间根目录运行。其实现会定位源码空间、发现其中的 ROS 包，并为缺失的顶层 `src/CMakeLists.txt` 初始化工作空间。`catkin_package()` 每个包调用一次，可导出头文件目录、库名称和 catkin 依赖，供下游通过 `find_package()` 或 pkg-config 获取。[catkin_make 源码](https://github.com/ros/catkin/blob/noetic-devel/bin/catkin_make)，[catkin_package 实现与参数说明](https://github.com/ros/catkin/blob/noetic-devel/cmake/catkin_package.cmake)

`04_cmake` 的 `wheelbot_kinematics` 与 `wheelbot_demo` 位于同一 CMake 构建图中，因此库目标的 `PUBLIC` include 路径和 C++11 编译特性能沿 `target_link_libraries()` 传给 `wheelbot_demo`。`05_catkin` 的 `wheelbot_core` 与 `wheelbot_ros` 是分开的 catkin 包，示例采用 catkin 变量导出：核心包通过 `catkin_package(INCLUDE_DIRS include LIBRARIES wheelbot_core)` 发布信息，ROS 包在 `find_package(catkin REQUIRED COMPONENTS ... wheelbot_core)` 后显式使用 `${catkin_INCLUDE_DIRS}` 与 `${catkin_LIBRARIES}`。C++11 由各包自己的 `CMakeLists.txt` 配置；示例通过各目标的 `target_compile_features(... cxx_std_11)` 声明语言特性要求。`catkin_package()` 的导出参数不包含 C++ 标准要求。[CMake target 使用要求](https://cmake.org/cmake/help/v3.16/command/target_link_libraries.html)，[catkin_package 导出参数](https://github.com/ros/catkin/blob/noetic-devel/cmake/catkin_package.cmake)

`package.xml` 使用格式二时，应声明 `<package format="2">` 与 `<buildtool_depend>catkin</buildtool_depend>`。`<depend>` 表示相应包同时用于构建、构建接口和运行阶段，适用于 `roscpp` 及 `wheelbot_core` 这类依赖。构建工具依赖仍用 `buildtool_depend` 表达。[REP-0140 格式二规范](https://github.com/ros-infrastructure/rep/blob/master/rep-0140.rst)

catkin 的 setup 脚本用于设置工作空间环境。典型顺序是先在终端加载 `/opt/ros/noetic/setup.bash`，再从工作空间根目录运行 `catkin_make`；构建完成后，在运行节点的终端加载 `devel/setup.bash`。setup 脚本会将工作空间前缀加入 `CMAKE_PREFIX_PATH` 等搜索环境，用于查找工作空间包及其构建产物。[catkin_tools 工作空间与环境说明](https://github.com/catkin/catkin_tools/blob/main/docs/mechanics.rst)

`catkin build` 由独立的 `catkin_tools` 项目提供。`catkin_make` 的实现会检查 build 与 devel 空间的工具标记；发现空间由其他工具生成时，提示清理空间或改用另一空间。课程主线统一使用 `catkin_make`；选讲 `catkin build` 时使用单独工作空间。[catkin_make 工具标记检查](https://github.com/ros/catkin/blob/noetic-devel/bin/catkin_make#L919-L992)，[catkin_tools 工作空间说明](https://github.com/catkin/catkin_tools/blob/main/docs/mechanics.rst)

## 易错点纠正表

| 易错理解或旧写法 | 课堂纠正 | 官方依据 |
| --- | --- | --- |
| `g++ -c file.cpp` 会直接得到可执行文件 | `-c` 只生成 `.o`。多个源文件各自编译后，再将所需对象文件交给链接器 | [GCC `-c`](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html) |
| 头文件声明已经包含函数实现 | 头文件用于共享接口声明；普通函数实现位于源文件，对应 `.o` 要参与链接 | [GCC 头文件说明](https://gcc.gnu.org/onlinedocs/cpp/Header-Files.html) |
| Make 会从 `#include` 自动推导所有头文件依赖 | 初始规则显式列出头文件；扩展时生成并 include `.d` 文件 | [GNU Make 自动依赖](https://www.gnu.org/software/make/manual/html_node/Automatic-Prerequisites.html) |
| Make recipe 前可以用空格代替 TAB | recipe 默认使用 TAB 起始。课堂练习保留真实 TAB | [GNU Make 规则语法](https://www.gnu.org/software/make/manual/html_node/Rule-Syntax.html) |
| `$@`、`$<`、`$^` 可直接写在普通前置条件列表 | 这些自动变量在 recipe 中使用；初学规则先用明确文件名表达依赖 | [GNU Make 自动变量](https://www.gnu.org/software/make/manual/html_node/Automatic-Variables.html) |
| `-MMD` 也包含系统头文件，移除头文件后总能正常重建 | `-MMD` 记录用户头文件；配合 `-MP` 生成空伪目标，`.d` 文件用 `-include` 加载 | [GCC 依赖选项](https://gcc.gnu.org/onlinedocs/gcc/Preprocessor-Options.html) |
| CMake 本身负责执行 C++ 编译 | CMake 配置项目并生成构建系统；`cmake --build` 调用所选构建程序 | [CMake 3.16.9 命令手册](https://cmake.org/cmake/help/v3.16/manual/cmake.1.html) |
| 把普通 CMake 的 `PUBLIC` 传播直接套用到 catkin 跨包 | `04_cmake` 由 `wheelbot_kinematics` 向同一构建图中的 `wheelbot_demo` 传播使用要求；`05_catkin` 由 `catkin_package()` 导出目录和库变量，`wheelbot_ros` 显式使用 `${catkin_INCLUDE_DIRS}` 与 `${catkin_LIBRARIES}`。C++11 在各包的 `CMakeLists.txt` 分别配置 | [CMake target 使用要求](https://cmake.org/cmake/help/v3.16/command/target_link_libraries.html)，[catkin_package 导出参数](https://github.com/ros/catkin/blob/noetic-devel/cmake/catkin_package.cmake) |
| `aux_source_directory()` 适合自动发现任意新增源文件 | 新文件可能不会触发重新配置；演示目标显式列出源文件 | [CMake 3.16.9 `aux_source_directory`](https://cmake.org/cmake/help/v3.16/command/aux_source_directory.html) |
| 从源码目录执行 `cmake .` 是课程的默认操作 | CMake 支持同目录构建；课堂用 `-S`、`-B` 将源码树和构建树分开 | [CMake 3.16.9 源码与构建目录](https://cmake.org/cmake/help/v3.16/manual/cmake.1.html) |
| `catkin_package()` 只负责声明包名 | 它会导出头文件目录、库和 catkin 依赖，供下游查找与使用 | [catkin_package 源码](https://github.com/ros/catkin/blob/noetic-devel/cmake/catkin_package.cmake) |
| 格式二用 `<depend>catkin</depend>` 声明构建工具 | catkin 作为构建工具使用 `<buildtool_depend>`；`<depend>` 用于同时具有构建、导出和运行需求的包 | [REP-0140](https://github.com/ros-infrastructure/rep/blob/master/rep-0140.rst)，[catkin_package 检查](https://github.com/ros/catkin/blob/noetic-devel/cmake/catkin_package.cmake) |
| `catkin_make` 与 `catkin build` 共用现有 build/devel 空间 | 两者由不同项目提供；本课为两个命令分开工作空间，主线只使用 `catkin_make` | [catkin_make 空间标记检查](https://github.com/ros/catkin/blob/noetic-devel/bin/catkin_make#L919-L992)，[catkin_tools 文档](https://github.com/catkin/catkin_tools/blob/main/docs/mechanics.rst) |
| 只加载 `/opt/ros/noetic/setup.bash` 就能运行本次工作空间的节点 | 运行工作空间产物前，在对应终端加载 `devel/setup.bash` | [catkin_tools 环境加载说明](https://github.com/catkin/catkin_tools/blob/main/docs/mechanics.rst) |

## 可直接用于讲稿的提示

- “`-c` 让每个源文件先变成自己的 `.o`。链接阶段再把对象文件和需要的库组合成程序。”
- “Make 根据目标与前置条件的时间戳决定是否执行命令。先写清依赖，增量构建才有可靠依据。”
- “CMake 记录目标、依赖和使用要求，再为本机选择的生成器写出构建系统。配置后使用 `cmake --build`。”
- “在普通 CMake 项目中，`wheelbot_kinematics` 的 `PUBLIC` 要求经链接传给同一构建图中的 `wheelbot_demo`。跨到 catkin 包时，查看 `catkin_package()` 导出的目录与库变量，以及 `wheelbot_ros` 对这些变量的显式使用。每个包分别配置 C++11。”
- “catkin 工作空间放多个包。`package.xml` 描述包与依赖，`CMakeLists.txt` 声明构建目标，`catkin_package()` 提供下游使用信息。”
