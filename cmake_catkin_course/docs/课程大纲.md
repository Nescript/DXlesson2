# CMake 与 catkin：从一条编译命令到 ROS 工作空间

## 课程定位

对象：能读懂 C++ 变量、函数和 `main()`，用过终端，对头文件和构建工具尚不熟悉的机器人队新成员。

时长：120 分钟。程序文件课前发给学生。课堂现场输入编译命令、编写核心构建规则，并修改少量源码。完整逐字敲入所有程序可安排为两次 90 分钟课。

环境：Ubuntu 20.04、G++、GNU Make、CMake 3.16 及以上。最后一段使用已配置的 ROS 1 Noetic 与 catkin。课程中的 catkin 示例面向现有 ROS 1 教学环境。相关版本背景见《官方依据与教学易错点》。

先修范围：学生认识函数调用、头文件和终端路径即可。发布订阅程序会提前提供，课堂集中讲构建关系和运行环境。

## 贯穿案例

为双轮底盘计算车体速度。先在终端显示计算结果，最后把同一个计算函数接入 ROS 节点。

| 输入或输出 | 符号与单位 | 默认数值 |
| --- | --- | --- |
| 左轮角速度 | ωL，rad/s | 2.0 |
| 右轮角速度 | ωR，rad/s | 4.0 |
| 轮半径 | r，m | 0.1 |
| 两轮中心距离 | L，m | 0.5 |
| 前进速度 | v = r × (ωL + ωR) / 2，m/s | 0.3 |
| 绕竖直轴角速度 | ω = r × (ωR − ωL) / L，rad/s | 0.4 |

这里采用差速底盘的平面运动学模型，约定 x 向前、z 向上、绕 z 正方向为逆时针。轮腿机器人课件中的照片用于引入场景，演示代码只计算上述简化模型。

前四阶段的预期输出保持一致：

```text
linear_x=0.300 m/s
angular_z=0.400 rad/s
```

## 每段的教学边界

### 第一段：单文件

必须讲清 `g++`、输入文件、`-o`、运行路径 `./`。`-std=c++11` 与警告选项按现成命令使用。预处理、汇编仅补充展示，避免一开始占用太多时间。

### 第二段：多文件

必须走完一次“声明可见，链接缺少实现”的演示。再解释 `-I` 与 `-c` 的作用。先只关注两个 `.cpp` 和一个头文件，到 CMake 段再增加库、应用和测试目录。

### 第三段：Makefile

主课只手写显式规则、依赖和命令，以及 `all`、`clean`、`.PHONY`。先让学生看懂依赖，再把自动变量、模式规则和自动头文件依赖作为扩展。每次修改源码前先让学生预测会重新编译哪些文件。

### 第四段：CMake

先写出能编译多个源文件的最小 `CMakeLists.txt`。再观察 `lib`、`app`、`tests` 的增长，逐步写成库目标、应用目标和测试目标。主课使用显式源文件列表、`target_include_directories()`、`target_link_libraries()` 和 `add_subdirectory()`。用 `PUBLIC` 讲清库的使用要求。`PRIVATE` 表达当前目标自己的依赖。

`cmake -S . -B build` 完成配置与生成，`cmake --build build` 调用已选构建工具。默认生成器由环境决定，教学机可以明确指定 `-G "Unix Makefiles"`。Ninja 仅用作课后对照实验。

### 第五段：catkin

主线统一使用 `catkin_make`。工作空间内提供两个包，分别承载计算库和 ROS 节点。程序里没有自定义消息生成，便于集中观察 `find_package(catkin ...)`、`catkin_package()`、`package.xml`、构建顺序和环境加载。

学生需要分别识别：工作空间、包、库目标、可执行目标和运行中的节点。`catkin build` 属于可选补充，另建工作空间练习。

## 现场故障设计

| 阶段 | 故意操作 | 典型结果 | 恢复动作 |
| --- | --- | --- | --- |
| 单文件 | 运行尚未编译的程序 | 文件不存在 | 先执行编译命令 |
| 多文件 | 只链接 `main.o` | 出现 `undefined reference` | 把 `kinematics.o` 加到链接输入中 |
| 多文件 | 把可供多个 `.cpp` 包含的普通函数定义写进头文件 | 可能出现多重定义 | 将普通函数实现放回 `.cpp`，头文件保留声明 |
| Make | 将命令前的 TAB 换成空格 | 常见报错为 `missing separator` | 恢复一个真正的 TAB |
| Make | 修改头文件后观察构建 | 依赖完整时相关目标文件重新编译 | 检查显式头依赖，扩展阶段观察 `.d` 文件 |
| CMake | 暂时移除应用对库的链接关系 | 可能先遇到头文件搜索失败，也可能遇到链接错误 | 恢复目标链接关系，重新配置并构建 |
| catkin | 新终端只加载系统 ROS 环境 | 当前工作空间的包可能无法被找到 | 加载本次工作空间 `devel/setup.bash` |

故障演示在复制出来的练习目录进行。课堂保留一份可运行的源码，方便立即恢复。

## 学生练习与验收

1. 把左右轮角速度都改为 3，运行后说明为什么角速度为 0。
2. 只修改计算函数的 `.cpp`，先预测重编范围，再用 `make` 验证。
3. 修改函数声明所在头文件，说明哪些目标文件依赖它。
4. 在 CMake 项目中增加一个可执行目标，复用已有计算库。
5. 在 ROS launch 中修改左右轮参数，观察 `/lesson2/body_twist` 的 `linear.x` 与 `angular.z`。

完成标准：能独立解释一次编译、一次链接、一次增量构建、一次 CMake 配置，以及一次 catkin 工作空间构建。能给现有库增加应用目标，并能把库通过 catkin 导出给另一个包使用。

## 课前准备

教师先运行 `scripts/probe_environment.sh`、`scripts/verify_cpp.sh` 和 `scripts/verify_ros.sh`。确认本机能构建所有阶段后，再把演示包发给学生。环境安装放到课前完成。

准备三个终端标签，分别用于编译、ROS master、节点或话题观察。清除会自动加载其他工作空间的终端设置干扰，明确每个终端加载的是哪一份环境。提前完成 ROS 首次构建，课堂仍展示实际构建命令。

演示入口和文件名以根目录 `README.md` 与各阶段 `README.md` 为准。逐段口述与操作顺序见《讲稿草稿》。
